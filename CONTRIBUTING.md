# Contributing

Thank you for considering a contribution to the Agentic Open-Source Engineering Methodology.

This repository is currently in private incubation. The contribution model is intentionally lightweight while the methodology is still being validated.

## What Makes a Good Contribution

Prefer changes that improve engineering decision quality rather than simply adding more terminology or more rules.

Before proposing a new principle, rule, or practice, ask:

1. Does it address a real engineering problem?
2. Is it reusable across more than one narrow scenario?
3. Is it a Principle, a Decision Rule, or a Practice?
4. Is it already covered by an existing principle?
5. Is it likely to remain useful as specific AI tools change?
6. Does it materially improve a decision or make agent work more verifiable?

## Contribution Expectations

- Keep changes focused and reviewable.
- Explain important trade-offs and exceptions.
- Update the corresponding Chinese or English document when changing bilingual normative content.
- Do not introduce private data, secrets, machine-specific paths, or unpublished project material.
- Avoid unnecessary dependencies and automation.
- Preserve the distinction between stable principles and fast-changing practices.

## Language

English and Simplified Chinese are both first-class documentation languages.

For major normative documents, changes should preserve semantic equivalence across language versions. Mechanical translation is not required; natural technical writing in each language is preferred.

## Pull Requests

A pull request should state:

- what problem it addresses;
- what layer it changes: Principle, Decision Framework, or Practice;
- why the change is justified;
- how it was validated;
- whether the paired language document was reviewed.

The project follows the meta-principle **Outcomes over Dogma**. Deviation from a default is acceptable when the trade-off is explicit and justified.
