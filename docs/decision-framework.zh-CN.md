# 决策框架

[English](decision-framework.md)

本方法论把核心原则视为强默认偏好，而不是绝对规则。本框架用于帮助开发者与 Agent 处理例外，使方法论既不滑向僵化教条，也不退化成无法约束工程行为的模糊偏好。

## 先明确项目结果

应用原则之前，应先把当前决策真正关心的项目结果说明到足够清晰。根据任务性质，可以包括：

- 项目目的与主要用户；
- 正确性与质量要求；
- 隐私、安全或 safety 边界；
- 性能与资源约束；
- 可维护性与运维成本；
- 兼容性承诺；
- 交付约束或其他明确项目目标。

不得假设“满足更多条方法论原则”就一定意味着项目结果更好。

## 决策闭环

使用：

`Default → Conflict → Trade-off → Exception → Evidence → Revisit`

### 1. Default — 明确默认原则

首先确定与当前问题相关的方法论原则或已有项目默认。默认值的意义在于减少重复争论，让项目行为更加一致。

### 2. Conflict — 识别真实冲突

明确真正发生的冲突，例如：

- 可移植性 vs 特定 provider 的能力优势；
- 本地执行 vs 易用性或算力要求；
- 依赖克制 vs 复用成熟基础设施；
- 新手简单性 vs 高级配置能力；
- Agent 快速执行 vs 可审查性与安全性。

不得为了给已经偏好的方案找理由而虚构冲突。

### 3. Trade-off — 分析实际权衡

比较真正重要的工程后果，而不是统计每个方案“满足了几条原则”。

根据任务性质考虑：

- 用户价值；
- 正确性与质量；
- 隐私与安全；
- 可靠性与可验证性；
- 性能；
- 可维护性；
- 运维与认知复杂度；
- 可移植性与锁定成本；
- 可逆性；
- 短期与长期成本。

只使用真正影响当前决策的维度。

### 4. Exception — 必要时允许例外

当现有证据表明非默认方案能够实质改善项目结果时，可以选择例外。

例外的作用范围应尽可能小。不得因为一次特殊情况，就把局部例外直接推广成新的项目级规则。

### 5. Evidence — 保留足够证据

记录足够的理由，让其他开发者或 Agent 能够理解为什么存在这次偏离。

证据强度应与影响范围成比例，可以是：PR 描述、简短 decision note、benchmark、测试结果、issue 讨论、运维约束或设计记录。

影响越大、越难回滚的例外，需要越强的证据。

### 6. Revisit — 条件变化后重新评估

例外只是当前条件下的工程决策，而不是永久真理。

出现以下情况时应重新评估：

- 底层工具或模型发生变化；
- 维护成本明显上升；
- 原始约束已经消失；
- 新证据推翻原有理由；
- 一个局部例外开始扩散到原本范围之外。

## 决策质量优先于“原则计数”

一个方案不会因为满足了更多条命名原则就自动更好。原则的作用是暴露重要工程问题，而不是建立评分游戏。

当原则冲突时，应优先选择最符合项目明确目的、主要用户、质量要求、风险边界、维护需求和当前约束的方案。

## 决策记录应与风险成比例

记录强度应与影响相匹配：

- **低风险：** 正常 commit 或 PR 说明通常足够；
- **中风险：** 明确写出 default、conflict、trade-off 和 exception；
- **高风险：** 应保留更持久的证据、备选方案、风险、回滚策略和 revisit 条件。

高风险示例包括：破坏性 migration、隐私或安全边界变化、provider lock-in、仓库 visibility 修改、重大依赖承诺以及不可逆的 Git history 修改。

当决策值得长期保存时，可以使用 [`templates/DECISION_RECORD.md`](../templates/DECISION_RECORD.md)。

## 修改方法论本身之前

修改核心原则前应先回答：

1. 当前到底存在什么反复出现、且现有方法论处理不好的工程问题？
2. 它是否具有跨项目价值，而不是一次性偶发现象？
3. proposed change 实际属于 Principle、Decision Rule 还是 Practice？
4. 如果属于 Principle，它主要是价值、默认偏好、约束、决策准则还是优先采用的手段？
5. 是否只需要澄清现有原则，而无需增加新原则？
6. 它是否来自长期工程属性，而不是短期工具趋势？
7. 有哪些真实项目证据支持修改？

如果这些问题无法得到有力回答，优先保持核心方法论不变。

方法论本身的修改还应遵循 [方法论治理](governance.zh-CN.md) 中的轻量规则。
