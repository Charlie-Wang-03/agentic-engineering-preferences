# Security Policy

Agentic Engineering Preferences is primarily a Markdown-first reference repository, but security issues can still arise in automation, agent-facing instructions, dependencies, or accidental disclosure.

## Supported Version

Only the latest state of the default branch is actively maintained. Historical releases and commits are preserved references, not separately supported release lines.

## Reporting a Vulnerability

Please do **not** open a public issue for a suspected vulnerability, leaked secret, or other security-sensitive report.

Use this repository's private vulnerability reporting / Security Advisory flow when available. If private reporting is unavailable, contact the maintainer privately using the contact information on the maintainer's GitHub profile.

Do not include real credentials, private project material, or unnecessary personal data.

## Security-Relevant Examples

Examples include:

- exposed credentials, private paths, or private data in the repository or history;
- workflow permissions broader than necessary;
- agent instructions that could cause unauthorized writes, destructive actions, secret disclosure, or unintended data transfer;
- vulnerable or untrusted automation dependencies;
- repository guidance that weakens an explicit privacy or permission boundary.

Ordinary disagreements about engineering preferences should use normal Issues or Pull Requests.
